# Agent instructions

## Code organization

- Organize application code by feature under `src/lib/features/<feature>/`, keeping each feature’s UI, logic, and private helpers together.
- Reach another feature only through its `index.ts` entrypoint.
- Extract shared modules into `src/lib/shared/` when multiple features need them; shared modules import no feature.
- Keep framework routes thin; compose feature modules there.

## UI SDK priority

Build every interactive control from UI SDK (`@ui-sdk/svelte`) primitives; UI SDK is the only headless UI library. `bits-ui`, `shadcn-svelte` and its `components.json` registry stay out of the repository.

## Chrome styling

Style On Water, Compass, map markup, routes and shared chrome with the semantic color, text size and spacing tokens in `src/app.css`; add a token there when chrome needs a new value. Raw values stay in the MapLibre style (`src/lib/features/map/base-style.ts`), SVG paint (`currentColor`, `none`, `url(#id)` or `var(--token)`) and safe-area insets.

## Comments

Code comments and lint or type suppressions follow `$no-comments`. Keep legal notices, public API contracts, formatter directives, concise evidence of external constraints, and suppressions of style-only or faulty rules with their reason. Fix the code behind a correctness or safety finding instead of suppressing it. Delete narration, headings, commented-out code, and stale rationale.

## Agent skills

### Issue tracker

Track each feature locally under `.scratch/<feature>/`: the spec at `spec.md` and one ticket per file at `issues/<NN>-<slug>.md`, numbered from `01`. Record triage state in a `Status:` line near the top and blockers in a `Blocked by:` line. Append discussion under a `## Comments` heading at the bottom.

### Triage labels

Use the five canonical triage labels as written: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, and `wontfix`.

### Domain vocabulary

Before exploring the codebase, read the root `GLOSSARY.md`, and use its terms in issues, tests, and code. Record decisions in code, executable checks, `README.md`, or this file.

### UI review

Before preparing or reviewing a UI refactor, read `.agents/skills/review-krab-ui/SKILL.md`; its handoff defines shared evidence and independent visual review.
